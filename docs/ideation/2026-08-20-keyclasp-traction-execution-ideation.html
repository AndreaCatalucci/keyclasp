Relevant Context

What the numbers say

  • The repo (AndreaCatalucci/keyclasp) was created 2026-07-08, last pushed 2026-08-13. Stars: 0. Forks: 0.
  • The package is not on the npm registry. npm view keyclasp returns 404. Install is npm install -g github:AndreaCatalucci/keyclasp only, which also compiles a native better-sqlite3 binding. That's real friction before anyone can try it. Update 2026-08-20: fixed, see idea 1.
  • A web search for "keyclasp" github secrets vault returns zero hits naming the project. There is no HN, Reddit, dev.to, or awesome-list presence. Discoverability isn't weak. It's absent.
  • A finished, on-brand landing page (index.html) and a prior validation-niches brief (2026-08-10-keyclasp-validation-niches-ideation.html) already exist. Since that brief, the only commits are product fixes (passphrase key-wrap, Touch ID fallback). None of its six outreach ideas have been executed.
  • The upstream fork parent, keyblind, is on npm at v0.6.0 with 13 published versions and dependencies on stripe, resend, vercel, and acme-client, scope far beyond a secrets vault. Keyclasp's git history shows a deliberate move away from it (commit e8db531: "wrap the data key with the passphrase and drop Keyblind"). That divergence (minimal core, no cloud dependencies, no MCP server surface) is a real, defensible difference and current messaging doesn't foreground it.
The blocker isn't which audience to chase. It's that the product has never been placed where that audience (or search engines, or npm) could find it. Every traction tactic downstream of "get discovered" is blocked until that's fixed.

Publish to the npm registry

Discoverability infrastructureConfidence 94%Complexity Low

Description. Run npm publish under the name keyclasp (confirmed available). This drops install to npm install -g keyclasp, gives the project an npm search hit, a downloads counter, and a surface that package-aware coding agents and dependency tools can discover on their own, none of which exist today.

Status
Done 2026-08-20. Published as keyclasp@0.1.1; npm view keyclasp version confirms it. README and docs updated to the plain npm install -g keyclasp form.
Area
Discoverability infrastructure
Basis
Direct: confirmed by npm view keyclasp (404, name free) and the README's own admission that install currently requires a GitHub URL plus a native compile step.
Rationale
Every other channel (launch posts, outreach, listings) sends people to an install step. Right now that step is the highest-friction version possible. Fixing it once pays off on every channel below.
Downsides
Registering the name also means owning its expectations: versioning discipline, a changelog, and no silent breaking changes once someone depends on it.
