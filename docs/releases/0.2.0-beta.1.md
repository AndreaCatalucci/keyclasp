# 0.2.0-beta.1 release notes

Status: exact release candidate qualified and durably staged; corrected content-provenance CI remains pending. The candidate is not tagged, published, or installed from the npm registry.

## Added

- Independent machine and interactive software data keys.
- Authenticated record custody bound into AES-GCM associated data.
- `lock`, `unlock`, and `inherit` transitions that atomically update policy and re-encrypt matching records.
- Interactive passphrase enrollment and rotation; removal remains unavailable.
- Backup-first migration from the public one-key format.
- Authenticated mixed same-machine restore and all-interactive portable restore.
- Metadata-only dual-key status, operator authorization gates, lifecycle serialization, and interrupted-operation recovery.
- A short-lived `Keyclasp.app` Touch ID helper whose run prompt shows the command, scope, selected secret names, and output-protection state without receiving secret values.

## Supported beta matrix

- macOS `arm64` with Node.js 24 or 26. macOS `x64` is unsupported and fails closed.
- glibc Linux with Node.js 24 or 26.
- Windows is unsupported and fails closed before vault creation or mutation.
- `better-sqlite3@13.0.3` removes the deprecated downloader. Reviewed N-API prebuilds for `arm64` and `x64` ship inside the exact tarball and are SHA-256 verified; explicit source builds use the bundled dependency sources.

## Security limits

- Machine custody uses a software-derived local identity, not Secure Enclave, TPM, hardware attestation, or theft-resistant custody.
- Explicit named selection limits disclosure but does not authenticate another process running as the same user.
- An approved child receives usable credentials and must be trusted.
- Output scanning covers injected values of at least eight characters and is accidental-leak containment, not an exfiltration boundary.
- Mixed backups remain bound to the source machine. Only all-interactive backups are portable with the passphrase.
- Hardware mode remains unavailable and status-only.

Publication, registry installation, tags, and a public GitHub release remain protected actions requiring explicit authorization.
